# radare2

`radare2` CLI에 대한 이진 분석 기술. 초점은 GUI에 의존하지 않고 명령줄을 직접 사용하여 정찰, 분석, 위치 지정, 내보내기 및 조명 수정을 완료하는 것입니다.

## 적용 범위

이 스킬은 사용자가 다음과 같은 의도를 가지고 있을 때 먼저 사용해야 합니다.

- `r2` / `radare2`를 사용하여 `exe`, `dll`, `so`, `elf`, `apk`, `dex`, `wasm` 및 기타 파일을 분석합니다.
- `rabin2`, `rasm2`, `radiff2`, `rahash2`, `rax2` 사용법을 물어보세요
- 명령줄 분해, 함수 보기, 문자열 보기, 가져오기 및 내보내기 보기, 상호 참조 확인 및 패치 수행이 필요합니다.
- `radare2` 배치 명령어, `-c` 자동화 명령어, `r2pipe` 스크립트 작성 필요

사용자가 명시적으로 GUI 반전, Hex-Rays 스타일 의사코드 또는 IDA 작업흐름을 원하는 경우 `ida-reverse`에 우선순위를 부여하세요. 웹페이지 JS 리버스엔지니어링인 경우 `js-reverse`가 우선됩니다.

## 먼저 환경을 확인하세요

`r2`가 아직 사용 가능하다고 가정하지 마세요. 첫 번째 확인:

```powershell
r2 -v
rabin2 -v
```

설치되어 있지 않은 경우 공통 설치 위치를 확인하거나 설치하라는 메시지를 표시합니다.

일반적인 Windows 실행 파일:

- `radare2.exe`
- `rabin2.exe`
- `rasm2.exe`
- `radiff2.exe`
- `rahash2.exe`
- `rax2.exe`
- `r2pm.exe`

## 포함 리소스와 제외된 자동화

현재 큐레이션에는 `references/cheatsheet.md`만 포함되어 있습니다. 아래 `scripts/recon.ps1` 설명은 상류 전체 패키지의 인터페이스 참고이며 이 저장소에서는 실행할 수 없습니다.

### `scripts/recon.ps1`

첫 번째 프로파일링에 적합한 표준 정찰 스크립트입니다. Will output:

- 기본정보
- section area
- 수입
- 수출
- 문자열
- 선택사항 `r2 -A` 자동 분석 요약

호출 방법:

```powershell
powershell -File "<skill-root>\radare2\scripts\recon.ps1" -TargetPath "C:\path\to\sample.exe"
```

`r2`를 사용한 자동 분석이 필요한 경우:

```powershell
powershell -File "<skill-root>\radare2\scripts\recon.ps1" -TargetPath "C:\path\to\sample.exe" -RunAnalysis
```

### `references/cheatsheet.md`

더 많은 명령 세부 정보, 일반적인 시나리오에 대한 템플릿이 필요하거나 구문을 빠르게 기억하고 싶다면 기억에서 추측하는 대신 이 치트 시트를 사용하세요.

## 알려진 현상

### Windows에서 가끔 `.sdb` 경고가 누락됨

`rabin2`에서 일부 PE 파일을 감지하면 다음과 유사한 경보가 나타날 수 있습니다.

```text
ERROR: Cannot find ...\share\format\dll\*.sdb
```

본체 출력이 여전히 정상적으로 반환되는 경우 일반적으로 기본 정찰 결론에는 영향을 미치지 않으며 먼저 분석을 계속할 수 있습니다. 이런 부수적인 경고 때문에 분석이 실패했다고 직접적으로 판단하지 마세요.

## 기본 원칙

### 1. 먼저 정찰한 다음 더 깊이 파헤쳐 보세요.

모든 데이터가 나오자마자 자동으로 분석하지 마세요. 먼저 경량 명령을 사용하여 파일 유형, 아키텍처, 진입점, 문자열 및 가져오기 테이블을 확인한 다음 `aaa`, `aaaa` 또는 직접 분석을 수행할지 결정합니다.

### 2. 최소한의 충분한 명령 우선순위 지정

`radare2` 많은 명령이 있으며 사용자에게는 일반적으로 가장 짧은 경로만 필요합니다.

- 파일 정보 보기: `rabin2 -I`
- 문자열을 보세요: `rabin2 -z`
- 가져오기 및 내보내기 보기: `rabin2 -i` / `rabin2 -E`
- 상호작용 분석: `r2 <file>` 이후 로컬 명령 실행

### 3. 수정하기 전에 주의하세요

사용자가 바이너리를 패치하려는 경우:

- 기본적으로 먼저 읽기 전용으로 열립니다: `r2 <file>`
- 분명히 수정이 필요할 때만 쓰기 모드를 사용하세요: `r2 -w <file>` 또는 세션 중 `oo+`
- 의도하지 않은 원본 파일 덮어쓰기를 방지하려면 변경하기 전에 위험에 대해 알아두십시오.

## 일반적인 작업 흐름

## 워크플로우 1: 신속한 정찰

바이너리 파일을 얻는 경우에 적합합니다.

현재 큐레이션에는 정찰 스크립트가 없으므로 아래 수동 명령을 기본으로 사용하세요. 다음 호출은 스크립트를 별도 도입하고 검증한 경우에만 사용할 수 있습니다.

```powershell
powershell -File "<skill-root>\radare2\scripts\recon.ps1" -TargetPath "sample.exe"
```

수동 최소 명령만 필요한 경우 다음을 사용하십시오.

```powershell
rabin2 -I sample.exe
rabin2 -z sample.exe
rabin2 -i sample.exe
rabin2 -E sample.exe
```

초점:

- 파일 형식, 비트 수, 아키텍처, 플랫폼
- 진입점 주소
- 의심스러운 문자열: URL, 경로, 오류 보고서, 레지스트리, 명령줄 매개변수
- 가져오기 기능: 네트워크, 파일, 암호화, 프로세스 주입, 레지스트리 작업

## 워크플로 2: 대화형 분석 기능

```powershell
r2 sample.exe
```

다음을 입력한 후 일반적으로 사용됩니다.

```text
aaa # 일반 자동 분석
afl # 목록 함수
iz # 목록 문자열
iS # 열 섹션 영역
is # 기호 목록
s entry0 # 진입점 플래그로 점프
pdf # 현재 함수를 분해합니다
VV # 비주얼 모드로 들어갑니다 (터미널이 적합한 경우)
q #나가기
```

설명:

- 기본 우선순위는 `aaa`입니다. 처음에는 더 무거운 `aaaa`를 사용하지 마세요.
- 표본이 크거나 분석 속도가 느린 경우에는 입구 근처 영역만 분석한 후 수동으로 확장하면 됩니다.

## 워크플로 3: 기본/핵심 논리 찾기

```text
afl~main
afl~sym.
iz~http
iz~error
axt <addr>
```

아이디어:

- `main`, 진입점, 문자열 참조부터 시작해 보겠습니다.
- `axt`를 사용하여 특정 문자열이나 주소를 누가 인용했는지 알아보세요.
- 기준점을 찾은 후 `s <addr>`, `pdf`

## 워크플로 4: 16진수 및 메모리 보기

```text
px 64 # 현재 주소에서 64바이트 16진수
pd 20 # 분해 명령 20개
psz # 현재 주소 문자열을 읽습니다.
pxa # 친숙한 16진수 보기
```

## 워크플로 5: 바이너리 패치

사용자가 명시적으로 파일 수정을 요청하는 경우에만 사용하세요.

```powershell
r2 -w sample.exe
```

입력 후 예를 들면 다음과 같습니다.

```text
s 0x401000
wa nop
wa jmp 0x401050
q
```

일반적인 쓰기 작업:

- `wa <asm>`: 어셈블리 쓰기
- `wx <hex>`: 원시 바이트 쓰기
- `q`: 종료(`-w` 모드의 쓰기 명령은 즉시 파일에 반영됨)

수정하기 전에 원본 파일을 백업하는 것이 가장 좋습니다. 사용자가 백업에 대해 언급하지 않는 경우 적어도 한 번은 상기시켜주세요.

## 워크플로우 6: 비대화형 자동화

일회성 출력 결과에 적합:

```powershell
r2 -A -q -c "afl;iz;ii;q" sample.exe
```

일반적으로 사용되는 매개변수:

- `-A`: 시작 시 자동 분석
- `-q`: 정숙 모드
- `-c`: 명령 문자열 실행

명령이 많은 경우 읽기 쉬운 순서로 우선순위를 지정하고 유지 관리하기 어려운 매우 긴 문자열에 넣지 마십시오.

정찰 스크립트를 별도 도입한 경우에는 검증된 짧은 스크립트부터 사용하고, 현재 큐레이션에서는 위 수동 명령을 유지하세요.

## 일반적으로 사용되는 하위 도구

### `rabin2`

정적 정보 추출에 적합:

```powershell
rabin2 -I sample.exe   # 기본정보
rabin2 -S sample.exe   # section area
rabin2 -s sample.exe   # 상징
rabin2 -i sample.exe   # 수입
rabin2 -E sample.exe   # 수출
rabin2 -z sample.exe   # 문자열
rabin2 -zz sample.exe  # 더 자세한 문자열
```

### `rasm2`

빠른 조립/분해에 적합:

```powershell
rasm2 -d "9090"
rasm2 -a x86 -b 64 "xor eax, eax"
```

### `radiff2`

두 바이너리를 비교하는 데 적합합니다.

```powershell
radiff2 old.exe new.exe
radiff2 -C old.exe new.exe
```

### `rahash2`

해시 계산에 적합합니다.

```powershell
rahash2 -a md5 sample.exe
rahash2 -a sha256 sample.exe
```

### `rax2`

기본 및 인코딩 변환에 적합:

```powershell
rax2 0x401000
rax2 4198400
rax2 -s hello
```

## 권장 분석 순서

알 수 없는 샘플이 발견되면 다음 순서로 수행하십시오.

1. `rabin2 -I` 형식, 아키텍처, 진입점 살펴보기
2. `rabin2 -z` 문자열을 보세요
3. `rabin2 -i` 가져온 기능 보기
4. 대화형 분석이 필요하시면 `r2`로 이동하세요.
5. 처음에는 `aaa`, 다음에는 `afl` / `iz` / `pdf`
6. 문자열 참조, 가져오기 호출 및 입력 프로세스를 통해 점차적으로 주요 기능을 찾습니다.

이 시퀀스의 장점은 노이즈가 적고 최대한 빠르게 방향 감각을 확립할 수 있다는 것입니다.

## Windows 고려 사항

- 경로에 공백이 있으면 명령을 올바르게 인용해야 합니다.
- 현재 단말기가 `r2`를 찾을 수 없다면 `PATH`이 방금 업데이트되었을 수 있습니다. 새 터미널을 열고 다시 시도해 보세요.
- 일부 샘플을 읽으려면 관리자 권한이 필요하지만 기본적으로 사용자가 명시적으로 필요로 하지 않는 한 권한을 적극적으로 에스컬레이션하지 않습니다.
- 의심스러운 샘플을 동적으로 디버깅하기 전에 오작동을 방지하려는 사용자의 의도를 확인하십시오.

## 출력 스타일

사용자가 명령만 원하는 것이 아니라 실제로 파일을 분석하기를 원하는 경우:

- 먼저 정찰 결과를 요약해 보세요.
- 그런 다음 문자열, 가져오기, 함수, 주소 등 주요 증거를 나열합니다.
- 마지막으로 다음 단계에 대한 제안을 하거나 심층 분석을 계속합니다.

명령을 수행하는 이유를 설명하지 않고 명령만 나열하지 마십시오.

## 일반적인 요청 예

### 예 1: exe 분석

사용자:`이 exe가 무엇을 하는지 봐줘. radare2면 돼`

처리 방법:

1. 먼저 `rabin2 -I/-z/-i`를 사용하세요
2. `r2`를 입력해야 하는지 결정하세요.
3. `aaa`, `afl`, `pdf`를 사용하여 항목과 키 문자열 참조를 더 자세히 살펴보세요.

### 예시 2: 문자열이 호출되는 위치 찾기

사용자:`이 오류 문자열이 어느 함수에서 트리거되는지 찾아줘`

처리 방법:

1. `iz~키워드`를 사용하여 문자열 주소를 찾습니다.
2. 참고 자료를 찾으려면 `axt <addr>`를 사용하세요.
3. `pdf` 이후 기준점 `s <addr>`로 이동

### 예 3: 점프 변경

사용자:`이 jne를 je로 바꿔줘`

처리 방법:

1. 먼저 목적지 주소를 확인하세요
2. 쓰기 모드로 들어가라고 명확하게 알려주세요.
3. `wa je <target>` 또는 직접 `wx`를 사용하세요.
4. 수정 후 분해하여 다시 확인해 보세요.

## 주문형 부트스트랩

현재 큐레이션에는 진입·설치 스크립트가 없으므로 radare2를 자동 설치하지 않습니다.

### 자동화 기능 경계

| 도구| 자동으로 설치 가능| 설치방법| 설명|
|------|-----------|---------|------|
| r2 | ✗ | 공식 릴리스 또는 운영체제 패키지 관리자 | 설치 후 `r2 -v` 확인 |
